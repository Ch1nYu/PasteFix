## 一、定位

> **把從聊天視窗複製的多行指令，變成可以一次貼進終端機的形式。**

只做兩件事：**去除共同縮排**、**合併續行**。其他一律不做。

---

## 二、為什麼要砍（決策紀錄）

原本的 `Normalizer` 做了七件事：去 fence、剝 prompt、刪 `#` 註解、去共同縮排、TrimEnd、合併續行、轉換行尾。實測與問答後，其中五件被否決：

| 規則 | 判決 | 理由 |
|---|---|---|
| 行尾轉換（LF↔CRLF） | **刪** | 實測否決。`paste-probe -Paste` 量到 WezTerm 把 LF 與 CRLF 送給應用程式時結果完全相同（都變 LF，總長皆 17 無增減）。PasteFix 只能在 LF/CRLF 之間選，所以它對行尾做的事在目標環境不可觀測。 |
| 剝 `$ ` / `> ` / `PS C:\>` prompt | **刪** | 使用者複製時會主動避開前綴符號，舉不出實際情境。附帶效果：`multiPrompt` 概念一併消失，而它是 BUG-2、BUG-4 與零寬 `\s*` 漏洞的共同母體。 |
| 刪 `#` 註解行 | **刪** | 同上，依附於 `multiPrompt`。 |
| 去 markdown fence | **刪** | 使用者用「複製程式碼」按鈕，fence 不會進剪貼簿。留著的理由只有「留著沒差」，而該理由已在 fence 這一題被否決——標準破例一次就等於沒有標準。 |
| `IsCommandShaped` gate | **刪** | 它存在的唯一理由是保護使用者不被有損轉換傷害。轉換分層之後（見第四節）這個保護沒有作用對象了。內容也是拍腦袋的字串標記（`Contains("yaml")`、`Contains("api:")`）。 |
| **去共同縮排** | **留** | 命中原始痛點：從聊天視窗框選複製會帶進整段縮排。保留相對縮排，所以 Python / YAML / here-string 不受損。 |
| **合併續行** | **留** | 命中跨 shell 的真實痛點：bash 用 `\`、PowerShell 用反引號，符號不同導致指令貼到另一個 shell 就壞。合併之後續行符號不存在，因此**工具不需要知道目標 shell**。 |

### 驗收標準（每條規則都要通過）

1. `Normalizer` 單一責任，行數砍半以上
2. README 一句話講完用途
3. **每條規則都要對得上一個實際遇過的情境，對不上就刪**

## 三、實作步驟

### 步驟 1 — 先把現況提交成安全點

目前工作區有一批未提交的修復（BUG-1/2/5 修好、測試 25→30 全過）。先 commit，讓後面的刪減有可回退的基準。

```
fix: preserve indent, keep in-code comments, guard continuation merge
```

### 步驟 2 — 重寫 `Normalizer.cs`

**刪除**：`FenceLine()`、`ShellPrompt()`、`PowerShellPrompt()`、`AnyPrompt()`、`NormalizeLineEndings()`、fence 剝除段、`multiPrompt` 計算與早退、prompt 剝除段、`#` 過濾、`TrimEnd()`。

**保留並拆成兩個公開進入點**：

```csharp
// AutoMonitor 用：只去共同縮排
public static string Dedent(string input);

// Alt+V / 立即清洗 用：Dedent + 合併續行
public static string Normalize(string input);
```

**行尾**：偵測輸入原本的分隔符並原樣重組，不做任何轉換。

**續行標記**：`\`、反引號、`&&`、尾端 `|`。

**合併的守衛條件**（三層，缺一不可）：

- 括號深度為 0（已實作，`BracketDelta`）
- 不在單引號或雙引號字串內 —— **待實作**
- 不在 here-string 內（`@"` … `"@`、bash `<<EOF`）—— **待實作**

守衛的失敗代價不對稱：漏合併只是要手動接一下，誤合併是**靜默改寫字串內容**且不會當場發現。所以守衛從嚴。

**合併時的細節**：續行段落要 `TrimStart()` 再接，否則會留下來源縮排造成的多餘空格（今天修過的 `docker run     -e FOO=bar` 問題）。

### 步驟 3 — 重寫 `TrayApplication.cs` 的清洗路徑

刪除 `IsCommandShaped()`（約 40 行）。`CleanClipboard` 改成：

```csharp
string cleaned = force
    ? Normalizer.Normalize(text)   // Alt+V / 立即清洗 / 雙擊
    : Normalizer.Dedent(text);     // AutoMonitor
```

分層的意義：AutoMonitor 你不會注意到它做了什麼，所以只准做結構保留的事；Alt+V 是你主動按的，按下去就是授權。**因此兩條路都不需要判斷內容是什麼**——整個 codebase 不再有任何啟發式規則。

### 步驟 4 — 重寫測試

**刪除**（規則已不存在）：`RemovesMarkdownFenceAndIndent`、`RemovesDollarShellPrompt`、`RemovesAngleShellPrompt`、`RemovesPowerShellPrompt`、`RemovesCommentLinesInPromptContext`、`KeepsCommentLinesInNonPromptContext`、`KeepsMultiLinePromptsAsSeparateCommands`、`HandlesCrLfInput`、`ConvertsLfInputToCrLfOutput`、`NormalizeLineEndings*`、`ReturnsEmptyForFenceOnlyInput`、`PowerShellVariablesAreNotPrompts`、`StillDetectsRealDollarPrompts`。連同 `PasteFix/examples` 裡對應的 fixture。

**保留**：`KeepsIndentForCodeWithoutPrompt`、`KeepsIndentForPythonCode`、`KeepsNonCommandMultiLineIntact`、`KeepsCodeWithTrailingAndAndUnmerged`、`KeepsCMacroBackslashInsideBracesUnmerged`、`MergedContinuationDoesNotKeepLeadingIndent`、`JoinsBackslashContinuations`、`JoinsDoubleAmpersandContinuations`、`NormalizeIsIdempotent`。

**新增**：

| 情境 | 斷言 |
|---|---|
| 反引號續行（PowerShell） | `` "Get-ChildItem `\n  -Path ." `` → 合併成一行 |
| 尾端管線續行 | `"Get-Process \|\n  Select-Object -First 3"` → 合併成一行 |
| 引號內的尾端反斜線 | `'echo "C:\path\"'` → **不**合併 |
| here-string 內不動 | `@"` … 內含 `\` 結尾的行 → 原樣保留 |
| 行尾原樣保留 | LF 進 LF 出、CRLF 進 CRLF 出 |
| `Dedent` 不合併 | 有續行標記的輸入經 `Dedent` 後仍是多行 |

**測試先寫再改**：每一條新增的守衛都要先有失敗測試。

### 步驟 5 — 重寫 `PasteFix/README.md`

必須包含四節：

1. **一句話定位**（第一節的那句）
2. **做什麼**：兩件事，各一個範例
3. **不做什麼**（明確邊界，防止三個月後又長回去）：
   - 不做跨 shell **翻譯**：`$VAR` 展開、`$(...)` 子殼層、`&&` 語意差異、`/` 對 `\` 路徑分隔符
   - 不碰行尾（附實測數據）
   - 不剝 prompt、不刪註解、不處理 markdown
   - 續行合併是唯一的跨 shell 例外，因為續行符號是**純語法雜訊、不帶語意**
4. **支援範圍**：只在 WezTerm + PowerShell 7.6 上驗證過，其他環境未測

### 步驟 6 — 反序案例寫進 README 當動機範例

標題定位成「這個工具**不**負責的那一段」，內容包含：

- 症狀：貼上多行腳本，行序整段顛倒，且 PowerShell 照反序真的執行（曾因此以錯誤順序刪檔）
- 逐層排除：剪貼簿行尾（LF/CRLF/CR 都會反序）→ 終端機（`paste-probe` 量到位元組正確無增減）→ PSReadLine（`-NoProfile` 正常）→ **profile**
- 根因：coreutils 的 `PSConsoleHostReadLine` 覆寫 + starship 多行提示符號，兩者同時存在才會壞
- 修法：移除該覆寫（不在 PasteFix 範圍內）

這一節的價值在於：它證明作者不只知道問題在哪，還知道**哪一段不歸自己管**。對公開專案而言這比多做幾個功能有說服力。

### 步驟 7 — 重新產生 `tools/manual-test.ps1`

刪掉對應已移除規則的案例，改成驗證兩件事 + 三層守衛。
