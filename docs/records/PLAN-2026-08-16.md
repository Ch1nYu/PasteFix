## 一、要修的四件事

| # | 問題 | 判決 |
|---|---|---|
| 1 | 貼上通道靠視窗類名白名單硬編碼：白名單外又忽略 `WM_PASTE` 的終端機（多數 GPU 終端）會「清好了卻靜默沒貼」 | **修**：決策抽成純函數 `PasteChannelSelector` 上測試，整張表可用 `settings.json` 的 `PasteChannels` 覆寫；未知視窗的預設通道改送 Ctrl+Shift+V 按鍵——貼不上時失敗是看得到的，且是終端機家族的貼上慣例。此預設是政策不是實測，須在 README 誠實標注，`"*"` 可改回 `WmPaste` |
| 2 | 剪貼簿自我觸發只有隱式防護（寫回內容 dedent 冪等 + 300ms debounce）；哪天 Normalize 不冪等就會自己觸發自己 | **修**：`OwnWriteGate` 記住 `GetClipboardSequenceNumber()` 寫回那一刻的序號，監聽路徑遇到相同序號直接跳過。冪等檢查保留，兩道防護獨立存在 |
| 3 | Alt+V 把剪貼簿前 100 字元寫進 `%APPDATA%` 的永久明文 log——密碼也會被複製 | **修**：`ClipboardSummary.Describe` 只輸出 `len=N`。`PASTEFIX_TRACE=1` 的 trace 檔**保持原樣**：自願開啟的診斷工具，就是為了看內容而存在 |
| 4 | `keybd_event` 是廢棄 API | **修**：換 `SendInput`，行為零變更的機械替換（含「先釋放實體 Alt」） |

明言不修：

- **反序貼上之謎**：README 已逐層論證發生在剪貼簿被讀取之後，PasteFix 修不了。
  `paste-probe.ps1` 待命。
- **Normalizer 的 YAML 傷害**：既有測試釘住的已接受取捨。

## 二、事先約定的 seams

| Seam | 形態 | 驗證的行為 |
|---|---|---|
| `PasteChannelSelector` | 純靜態 | 視窗類名＋使用者覆寫 → 貼上通道 |
| `ClipboardSummary` | 純靜態 | 剪貼簿文字 → 無內容的 log 描述 |
| `OwnWriteGate` | 純類別（序號進出） | 只忽略自己寫回觸發的事件，外來複製照常處理 |

`Normalizer` 不動。SendInput 與 end-to-end 貼上屬無 seam 的 Win32 行為，不硬上
單元測試，靠 `tools/manual-test.ps1`（含真實 Alt+V）驗證。
