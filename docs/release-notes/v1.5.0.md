v1.5.0 acts on two weeks of log evidence. Single Line is now a one-shot action instead of a mode that stays on. Writes from programs that only borrow the clipboard are left alone, and invisible characters copied from web pages are fixed.

## What changed

**1. Single Line, One Copy at a Time**

- Every automatic clean now runs Smart Continuation. The **處理模式** submenu is gone, replaced by the tray item **壓成單行（這一次）**, which flattens only the copy on the clipboard.
- The evidence: Single Line ran for 13 of 1025 logged copies. In the month before that, it was switched on and off 32 times, five times within a single minute. What was wanted was "this copy, flattened", not "every copy from now on". A mode that stays on is a wrong mode waiting to be forgotten.
- It flattens what you originally copied, not the Smart Continuation result already on the clipboard. **還原上一次清洗** afterwards therefore gives back the original copy.
- The one-shot is logged as `mode=SingleLine`, so the log stays comparable with v1.4.

**2. Programs That Borrow the Clipboard Are Left Alone**

Dictation tools such as LazyTyper put text on the clipboard, paste it, and put the previous content back about 0.72 s later. On 2026-10-27 that was a third of all clipboard events. The monitor now skips a write when:

- the writer tagged it with the Windows convention `ExcludeClipboardContentFromMonitorProcessing` (or `Clipboard Viewer Ignore`), or
- the writer's process is listed in `IgnoredProcesses` in `settings.json`. The default is `["LazyTyper"]`, matching is case-insensitive, and `.exe` is optional. An empty list turns this off.

Skipped writes are logged as `monitor skipped: owner=… reason=…`. Monitor log lines now end with `owner=<process name>`, which is a name and never content. If a program keeps appearing where you copied nothing, add its `owner=` name to the list.

Finding the writer takes two Win32 calls, `GetClipboardOwner` and `IsClipboardFormatAvailable`. Neither opens the clipboard, so this adds no `CLIPBRD_E_CANT_OPEN` path, and a skipped write never reads the clipboard text at all. Manual cleans are never filtered: **立即清洗**, the hotkey and **壓成單行（這一次）**.

**3. Invisible Characters**

- No-break spaces and other space lookalikes (U+00A0, U+2000–U+200A, U+202F, U+205F) become ordinary spaces.
- Zero-width characters (U+200B, U+2060, U+FEFF, U+00AD) are removed.
- A `git commit` copied from a web page can arrive with a no-break space, which pwsh reads as one word. It is now two words again. Indentation made of `&nbsp;` is now seen by dedent and by prompt and fence detection.
- Anything visible is left as copied: curly quotes, dashes, and the full-width space U+3000. Characters with meaning are kept too: zero-width joiner and non-joiner, used in emoji sequences, Persian and several Indic scripts.
- The `cleaned:` line gains `chars=N`, appended after `mode=` so existing queries still match.

## Not in this release

An HTML reader was built and then removed in the same cycle. It used the clipboard's CF_HTML to keep `<code class="language-python">` blocks multi-line under Single Line. It changed behavior in too few cases to justify two extra clipboard reads per copy and a hand-kept list of language names. The one-shot action addresses the same problem more directly. Details are in `docs/records/WORKLOG-2026-10-27.md`.

## Tests

- 187 unit tests (was 150). The new ones cover invisible-character fixes, the monitor filter, `IgnoredProcesses` settings validation, the one-shot source selection in `LastClean`, and the `chars=` log field.
- `tools/toggle-test.ps1`: 14 runtime checks.
  - A v1.4 `settings.json` with `"Mode": 1` no longer flattens automatic cleans.
  - A write tagged `ExcludeClipboardContentFromMonitorProcessing` is left uncleaned and logged as skipped.
  - Monitor log lines carry `owner=`.
- `tools/verify-v14.ps1`: 17 end-to-end checks through the real tray menu. New ones: **壓成單行（這一次）** flattens one copy, logs `mode=SingleLine`, undoes to the original copy, and leaves the next copy multi-line.

## Install

Unchanged: run `PasteFix.exe`. It is a self-contained single file and is not code-signed (SmartScreen: *More info* → *Run anyway*).

Your existing `settings.json` loads as-is:
- `Mode` is ignored and no longer written back.
- `IgnoredProcesses` is the only new key, and defaults to `["LazyTyper"]`.
