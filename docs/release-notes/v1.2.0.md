v1.2.0 unifies the entire cleaning pipeline into background AutoMonitor, removes the redundant Alt+V hotkey and keystroke simulation, and adds single-instance mutex protection.

## What changed

**1. Unified "Copy-to-Fix" Pipeline (Zero extra keystrokes)**
- Previously, AutoMonitor only performed Dedent, while joining continuations required pressing Alt+V.
- In v1.2.0, the pipeline is fully unified: whenever you copy text, AutoMonitor automatically runs the complete normalization (Dedent + margin repair + continuation joining) within 300ms in the background.
- You can simply use standard `Ctrl+V` or mouse right-click to paste into WezTerm, Windows Terminal, or any application.

**2. Removed Alt+V Hotkey & Window-Class Paste Simulation**
- Eliminated global hotkey registration (`WM_HOTKEY`) and `SendInput` keystroke injection.
- No more hotkey collisions with other applications, no stuck modifier keys, and zero accidental keystroke side-effects.
- Simplified `settings.json` to a single toggle: `AutoMonitor`.

**3. Single-Instance Mutex Protection**
- Added a named system mutex (`PasteFix_App_SingleInstance_Mutex`) to prevent multiple background instances from running simultaneously and competing for clipboard events.

**4. Reverse-Paste Root Cause & Resolution**
- Investigated and resolved the multi-line reverse paste issue in PowerShell on Windows:
  - Cause: Setting `canonicalize_pasted_newlines = "LineFeed"` in terminal emulators (e.g. WezTerm) forces raw `\n` characters into the Windows ConPTY pipeline, causing PSReadLine asynchronous continuation parsers to process multi-line streams in reverse order.
  - Solution: Retain native Windows line breaks (`CRLF` / `CR`) to ensure strictly ordered, non-inverting execution.

## Install

Unchanged — run `PasteFix.exe`, self-contained single file, ~51 MB, not code-signed (SmartScreen: *More info* → *Run anyway*).
