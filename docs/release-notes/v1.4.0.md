v1.4.0 answers the question the log could not: did it work, and if it did not, can I get the original back? It also strips the wrapper a copy arrived in, and adds an optional global hotkey.

## What changed

**1. A Successful Clean Is Now Visible**

- Every clean that changes the clipboard writes one line to `%APPDATA%\PasteFix\pastefix.log`:
  `cleaned: len=62->48 lines=3->3 containers=Fence`
- Sizes, line counts and which wrapper was removed — never the text. The `len=N`-only rule for clipboard contents is unchanged.
- Before this, only *failures* were logged. `pastefix.log` shows zero successful cleans between 2026-09-07 and 2026-10-12 while the tool was running: a working Pastefix left no evidence it had worked, so there was no way to tell "nothing needed cleaning" from "cleaning never ran".

**2. Undo the Last Clean**

- The tray menu has **還原上一次清洗**. It puts the text from before the last write-back back on the clipboard.
- It refuses when the clipboard no longer holds what the clean produced — something else was copied since, and overwriting that would be a second unrequested replacement. The restore is then dropped, and the menu says so.
- Held **in memory only**. A restore file would defeat the reason the permanent log carries only `len=N`: clipboard contents can be passwords.
- If the clipboard is momentarily busy, the restore fails but the way back is kept, so a moment of contention does not cost you the only undo.

**3. Wrapper Stripping**

A copy from a chat window often arrives wrapped. Pastefix now removes a wrapper when it provably covers the entire copy:

| Wrapper | Example | Result |
|---|---|---|
| Markdown fence | ` ```bash ` … ` ``` ` | markers removed, contents kept |
| Shell prompt gutter | `PS C:\Users\me> echo one` on every line | prompts removed |
| Line-number gutter | `42: echo one` / `43: echo two` | numbers removed |

Wrappers chain: a fenced PowerShell block with prompts inside loses both.

**Everything else is left alone**, deliberately:

- A fence that does not wrap the whole copy, or is unclosed, or contains another fence-shaped line.
- Mixed prompt styles, or one prompted line among plain ones.
- A single `$ npm install` — a gutter needs at least two lines to have a side.
- Markdown ordered lists (`1. Run the installer`). `.` and `)` are list syntax; a gutter uses a tab, a colon or a pipe. No structural test can tell a list from a gutter, so list syntax is not treated as a gutter at all. Numbered code blocks written that way are a visible miss you can undo, which is the trade this tool always takes over silent damage.

This is **not** the line-by-line guessing removed in the 2026-08-09 fix. No rule here decides which line is a command: the wrapper either covers everything or it is not a wrapper, and text with no wrapper is returned byte for byte.

**4. Optional Global Hotkey**

- **Ctrl+Alt+Shift+V** cleans the clipboard on demand, for copies made while the monitor was off or before Pastefix started. **Off by default**; enable it from the tray menu.
- If another program already owns the combination, Pastefix says so and shows the item unchecked rather than pretending the key works.
- Registered with `RegisterHotKey`, which asks Windows to deliver `WM_HOTKEY`. It sends no keystrokes and installs no keyboard hook — the ban added in v1.2.0 is on synthesising input (`SendInput`/`keybd_event`), which once opened dozens of WezTerm tabs. Owning a key combination is a different thing, and v1.2.0 removed both at once.

## Tests

- 148 unit tests (was 98), adding container stripping (fence, prompt, gutter, and every guard above), restore decisions, hotkey settings validation, and the log summary format.
- `tools/manual-test.ps1`: 18 clipboard smoke cases, including five container cases and five guards.
- `tools/toggle-test.ps1`: 13 runtime checks against the real executable — AutoMonitor off, both modes, mode persistence across a restart, the successful-clean log line, that the log leaks no content, and hotkey registration on and off.
- `tools/verify-v14.ps1`: 11 end-to-end checks that drive the actual tray menu through `tools/tray-menu.ps1` — the menu is wired to the code, a real clean writes a real log line, the restore puts the original text back, and it refuses to overwrite content copied since the clean. The menu is driven by posting the `NotifyIcon` callback message and invoking the item through UI Automation: no `SendInput`, no mouse coordinates, no keyboard hook, so it cannot repeat the failure that got input simulation banned.

The fence guard in `tools/manual-test.ps1` had been asserting on `'''bash` rather than backticks since it was written, so it never tested a real fence. PowerShell treats a backtick as an escape character inside double-quoted strings; the literals are now built from `[char]0x60`.

## Install

Unchanged — run `PasteFix.exe`, self-contained single file, not code-signed (SmartScreen: *More info* → *Run anyway*).

Your existing `settings.json` loads as-is; `HotkeyEnabled` is the only new key and defaults to off.
