v1.1.0 hardens the edges around the two things v1.0.0 already did. The
normalizer is untouched; what changed is everything around it.

## What changed

**The paste table is now yours.** When Alt+V fires in a window Pastefix doesn't
know, it now sends **Ctrl+Shift+V keystrokes** instead of `WM_PASTE`. Honest
labelling: the two built-in rows (WezTerm → Ctrl+Shift+V, Windows Terminal →
Ctrl+V) are measured facts; the new default is *policy* — Ctrl+Shift+V is the
terminal-family paste convention, and a keystroke that does nothing is a
**visible** failure, whereas unknown GPU terminals drop `WM_PASTE` silently
after the clean already succeeded. If you spend your Alt+V presses in plain
Edit controls, point the `"*"` row back at `"WmPaste"`.

The whole table lives in `%APPDATA%\PasteFix\settings.json`:

```json
"PasteChannels": {
  "org.wezfurlong.wezterm": "CtrlShiftV",
  "CASCADIA_HOSTING_WINDOW_CLASS": "CtrlV",
  "*": "CtrlShiftV"
}
```

Add a row for your terminal's window class (the log at
`%APPDATA%\PasteFix\pastefix.log` prints the class of whatever Alt+V fired in),
or change `"*"` — the row that stands for every unlisted window. Existing
settings files gain the field automatically on first run.

**The log no longer stores clipboard contents.** Alt+V used to write the first
100 characters of the clipboard into its permanent log; passwords get copied
too. It now records the length only (`len=…`). The opt-in `PASTEFIX_TRACE=1`
file still shows full content — it exists precisely for debugging.

**Self-triggered clipboard events are now skipped structurally.** Pastefix
writes its cleaned text back to the clipboard while listening for changes;
until now that was safe only because the written-back text was
dedent-idempotent. The clipboard's own sequence number now tells the writes
apart, so a future normalizer that isn't idempotent still can't loop.

**Internal:** the deprecated `keybd_event` call was replaced with `SendInput`
(same keys, same order, including the physical-Alt release).

## Install

Unchanged from v1.0.0 — run `PasteFix.exe`, self-contained, ~49 MB, not
code-signed (SmartScreen: *More info* → *Run anyway*).

## Still true from v1.0.0

- The margin repair remains unsound for YAML multi-line plain scalars — a
  deliberate, test-pinned trade.
- The reverse-order paste into PowerShell remains out of reach: it happens
  after the clipboard is read.
